## 主要改进

1. **补充输入及反馈的可访问性。** 为输入增加关联 label；对搜索状态使用合适的 `role="status"` 或 `aria-live="polite"`，使加载完成和无结果变化可以被辅助技术感知。placeholder 不能替代清晰的字段标签。
2. **把关键异步路径纳入联动测试。** 原 Hook 测试的 deferred Promise 很适合固定乱序，应保留；再用真实 App + Hook 验证加载中清空、清空后旧请求完成，以及旧请求先完成时不能关闭新请求的 loading。当前实现已经通过这些评审场景，这项是验证完整性建议，不是功能失败。
3. **扩展真实 API 时定义错误契约。** 当前 searchItems 只 resolve，所以缺少 catch 不构成本题普通路径缺陷。若以后改用可能 reject 的请求，需要增加错误状态并在未取消时结束 loading，否则会产生未处理拒绝及持续加载。cancelled 当前只忽略结果，不会停止底层计时器；本题规模合理，无需为此强加 AbortController 或防抖要求。

不要求全局状态、缓存、网络请求或更多组件。搜索开销为扫描数据集及字符串匹配，本题小规模本地数据下无需额外索引。拼写 `keywork`、`abord` 可顺手修正，不主导分数。
