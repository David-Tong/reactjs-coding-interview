## 改进建议

1. **使用用户身份作为 key**：建议将 `<li key={idx}>` 改为 `<li key={user.email}>`，当前模拟数据的邮箱唯一。页内索引在翻页时会复用给不同用户；当前纯文本展示可正确更新，但如果列表项增加内部状态，可能保留上一个用户的状态。
2. **提高测试有效性**：描述为“多次点击第一页 Previous 不改变页码”的用例没有执行点击；“计算总页数”的用例只验证测试内部的计算，没有检查组件行为。建议围绕用户可观察的翻页结果验证，减少重复断言。
3. **修正测试中的末页条数公式**：`totalUsers % pageSize` 在非空数据量恰好整除时得到 0，当前 18 条数据不会触发。可使用 `((totalUsers - 1) % pageSize) + 1`，或对当前固定数据直接断言 3 条。这是测试维护性问题，当前分页实现没有这个错误。
4. **适度简化代码**：`pageSize` 不会变化，可直接声明为常量；当前数据量很小，`useMemo` 可以省略。测试已有 `afterEach(cleanup)`，各处重复的 `cleanup()` 也可精简。这些属于可读性建议，无需增加组件、Hooks 或额外功能。
