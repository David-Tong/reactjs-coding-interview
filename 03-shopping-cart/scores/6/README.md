## 主要改进建议

1. **完善表格与反馈语义。** 表头改为 `th scope="col"`；可为按钮提供包含商品名的可访问名称，例如“添加 Java 一件”。错误区域可使用合适的 alert/live 语义。`onAdd` 的错误文案应表达库存不足或商品不存在，当前误写为移除失败。这些是体验及语义问题，不代表核心增减操作缺失。
2. **按需要加强状态一致性。** 当前两份状态由同一事件同步更新，对本题现有数据和逐次用户点击合理，不要求为了评分强制改用 reducer。不过校验使用当前渲染中的数量，同一批次重复调用同一回调可能都通过校验，而后续函数式更新会累计执行。此场景未动态验证，也不是已复现的普通点击故障。若未来支持批量操作，可把校验和相关数量更新放到同一次纯状态转换，或从固定总库存和购物车数量派生剩余库存。
3. **补充有价值的联动验证。** Cart 已验证多商品合计；再通过真实 App 添加两种商品并移除其中一种，能验证另一种商品及总价不会被误改。如果保留错误分支，可验证非法操作不改变数量，以及成功操作后错误消失。正常 UI 会隐藏零数量行，不应要求额外暴露非法操作入口来测试。

商品名在当前固定且唯一的数据中可用作 key 和查找条件；扩展为可重名商品时再引入独立 ID。`carrItems` 拼写可顺手修正，不主导评分。不要求添加全局状态、持久化、复杂性能优化或更多组件。
