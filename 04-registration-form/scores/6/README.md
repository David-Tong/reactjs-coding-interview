## 主要改进建议

1. **完善字段与反馈的可访问性。** 为每个输入提供关联 label，通过 aria-describedby 关联错误，并在校验失败时设置 aria-invalid；为提交状态提供合适的 status/live 语义。当前视觉上的相邻关系不能替代程序化关联。
2. **修正邮箱校验边界。** 当前正则不允许 @ 前出现连字符，会拒绝常见合法地址；对域名的限制也较宽松。应覆盖常见合法与非法输入，无需为本题实现完整邮件地址标准解析器。若决定容忍首尾空格，应在校验与提交时采用一致的处理方式。
3. **明确校验提示优先级。** 使用互斥分支，优先报告必填错误，再检查格式或密码一致性，避免后面的检查覆盖前面的提示。可将校验提取为纯函数以便阅读和测试，不要求额外拆组件或引入表单库。
4. **补齐关键行为验证。** 在一次测试中模拟首次提交失败、保留输入并再次成功，验证错误被新的提交状态替换；明确断言校验失败后所有已填值保留。再补合法邮箱边界及 label/错误关联验证。当前 DOM 结构定位方式与实现耦合较强，完善 label 后可使用 getByLabelText。

不要求全局状态、真实后端、复杂架构或额外密码强度规则。禁用按钮已通过普通重复点击场景的测试；不将未经验证的其他提交路径认定为已复现缺陷。
